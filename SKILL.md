# Feishu Sync

A cross-platform skill for bidirectional synchronization between local Markdown repositories and Feishu (飞书) / Lark Wiki spaces.

## ⚠️ Critical Warning: Comment Anchor Fragility

**Using `overwrite` to push a document will break comment anchors in Feishu.**

- Comments still exist in the API, but become **invisible in the Feishu UI**.
- This is because `overwrite` rebuilds the underlying document block structure, and Feishu comments are anchored to specific block IDs / positions.

**Using `block_replace` also breaks comment anchors on the replaced block.**

- The replaced block gets a new block ID, so any comments anchored to it will show as **"原文已被删除"** (original text deleted) in the Feishu UI.
- The comment content and replies are preserved, but the anchor to the document text is lost.

**Always prefer `str_replace` for comment-safe updates.** Use `block_replace` only when you must change block structure (e.g., splitting one block into two), and accept that comments on the replaced block will become orphaned.

## Onboarding Guide

When this skill is activated, follow this orchestration flow:

1.  **Status Check**: 
    -   Check if `lark-sync.json` exists.
    -   Run `lark-cli auth status` to check login. If not logged in, guide through `lark-cli auth login`.
2.  **Discovery (Space)**:
    -   If no config, run `lark-cli wiki spaces list` and present the list to the user nicely in the chat.
    -   Ask the user to choose a space or provide a Wiki URL.
3.  **Scenario Selection**:
    -   **Scenario 1 [Sync Existing]**: If the user has local files, run `python3 .../sync.py init`.
    -   **Scenario 2 [Clone]**: If the user wants to clone, ask for the **Feishu Wiki URL** directly.
4.  **Execution**:
    -   Call specific `sync.py` commands (`init`, `pull`, `push`, `clone`) with the necessary flags.

## Core Commands (for AI to use)

- **Initialize Config**: Create `lark-sync.json` manually with the selected `space_id`.
- **Clone from URL**: `python3 sync.py clone --url <URL>` (Ensure script supports direct URL flag).
- **Pull**: `python3 sync.py pull` — Fetch latest from Feishu.
- **Push (Safe)**: `python3 sync.py push --strategy patch` — Apply precise patches without destroying comments.
- **Push (Dangerous)**: `python3 sync.py push --strategy overwrite` — Only if user explicitly accepts the comment destruction warning.
- **View Comments**: `python3 sync.py comments` — List all unresolved comments.
- **Reply to Comment**: `python3 sync.py reply <filepath> <comment_id> <message>`.
- **Inspect Blocks**: `python3 sync.py blocks <filepath>` — Show block tree for precise editing.
- **Position Images**: `python3 sync.py inline-images` — Upload missing local images and place Feishu image tokens directly under matching `> 图示：...` anchors.
- **Refresh Images**: `python3 sync.py inline-images --refresh` — Re-upload changed local images and replace old Feishu image tokens at the same anchors.
- **Verify Images**: `python3 sync.py inline-images --verify` — Check current remote image placement without changing Feishu.

## How It Works

This skill uses a Python helper and `lark-cli` to bridge local Markdown with Feishu Wiki.
- The AI acts as the **Orchestrator**, handling selection and configuration.
- The Python script acts as the **Executor**, handling heavy-lifting API calls and file processing.

## Configuration Reference

The script reads its configuration from **`lark-sync.json`** in the current working directory (project root).

### Minimal config (auto-generated by setup)

```json
{
  "space_id": "YOUR_WIKI_SPACE_ID"
}
```

### Full config (only add what you need)

```json
{
  "space_id": "YOUR_WIKI_SPACE_ID",
  "domain": "www.feishu.cn",
  "state_file": "sync_state.json",
  "include_patterns": ["**/*.md"],
  "exclude_patterns": ["node_modules/**", ".*/**", "dist/**"],
  "readme_title": "My Project Root Doc",
  "title_mappings": {
    "docs/guide/Index.md": "Guide"
  },
  "visual_image_dirs": ["public/course-visuals-png"],
  "visual_image_autodiscover": true,
  "visual_images": [
    {
      "file": "Phase1-Basic/1.1-Introduction.md",
      "caption": "国际税务不是一种税，而是一套分账规则",
      "image": "public/course-visuals-png/1.1-global-tax-map.svg.png"
    }
  ]
}
```

## Push Strategies Explained

### Image Placement: `inline-images`

Use this when local Markdown has visual anchors like:

```md
> 图示：跨境付款预提税判断流程。飞书版以本节下方的流程表和 Checklist 作为可编辑图表呈现。
```

Run:

```bash
python3 ~/.claude/skills/feishu-sync/scripts/sync.py inline-images
python3 ~/.claude/skills/feishu-sync/scripts/sync.py inline-images --refresh
python3 ~/.claude/skills/feishu-sync/scripts/sync.py inline-images --verify
```

What it does:

1. Reads `sync_state.json` to map local files to Feishu `docx` tokens.
2. Reads `visual_images` from `lark-sync.json`, or auto-discovers images from `visual_image_dirs` by matching the file prefix such as `1.3-*`.
3. Uses `lark-cli docs +media-insert` only as a staging step if the remote document does not yet have enough image tokens. This command appends images to the end of the document, so it is not the final layout.
4. Fetches the remote Lark-flavored Markdown, removes loose image tags, reinserts each `<image token="..."/>` immediately after the matching `> 图示：...` anchor, and updates the document.
5. Verifies that every image appears after its matching anchor and before the next `图示：` anchor.

Use `--refresh` when the local image file changed, for example when replacing oversized desktop diagrams with mobile-safe diagrams. The command uploads fresh images first and uses the newest tokens for final placement.

Why not directly create a new image block and reuse the old token? Feishu Docx Block API can create image blocks (`block_type: 27`), but a token uploaded for one image block may fail when reused in another block with `1770013 relation mismatch`. The safer flow is to stage the image inside the target document first, then reposition the document-scoped image token.

**Important:** this command performs an overwrite after reordering image tokens, so it has the same comment-anchor risk as overwrite. Use it before review comments are created, or after confirming that preserving comment anchors is not required for the affected docs.

### Strategy 1: `patch` (Recommended, Comment-Safe)

Create a `patches.json` file that describes precise, surgical edits:

```json
{
  "Global Tax Course 101/Phase1-Basic/1.1-Introduction.md": [
    {
      "mode": "str_replace",
      "pattern": "旧文本",
      "content": "新文本"
    },
    {
      "mode": "block_replace",
      "block_id": "doxcnxxxxx",
      "content": "### New Heading\nNew paragraph content."
    },
    {
      "mode": "block_insert_after",
      "block_id": "doxcnxxxxx",
      "content": "**Additional info**: ..."
    }
  ]
}
```

Then run:
```bash
python3 ~/.claude/skills/feishu-sync/scripts/sync.py push --strategy patch
```

**Why this is safe:** `str_replace` only modifies the matched text within a block. Other blocks are untouched, so comment anchors remain intact. `block_replace` replaces the entire block, which orphans any comments anchored to that block.

**How to find block_id:**
```bash
python3 ~/.claude/skills/feishu-sync/scripts/sync.py blocks "path/to/file.md"
```

### Strategy 2: `str_replace` (Interactive)

For quick one-off edits without creating patches.json:

```bash
python3 ~/.claude/skills/feishu-sync/scripts/sync.py push --strategy str_replace --target "path/to/file.md"
# Script will prompt for pattern and replacement text interactively
```

### Strategy 3: `overwrite` (Use with Extreme Caution)

Replaces the entire document content. **Will destroy comment visibility.**

```bash
python3 ~/.claude/skills/feishu-sync/scripts/sync.py push --strategy overwrite
# Script will require typing 'yes' to confirm
```

## Best Practices

1. **Never use `overwrite` if the document has active review comments.** Use `patch` or `str_replace` instead.
2. **Run `init` after structural changes** — When files are renamed or new top-level wiki nodes are added, re-run `init` to rebuild `sync_state.json`.
3. **Version-control `sync_state.json`** — It is the source of truth for the local↔remote mapping. Commit it so teammates share the same mappings.
4. **Pull before editing** — To avoid overwriting remote changes, always `pull` before starting local edits.
5. **Pull destroys un-pushed local changes** — Running `pull` will overwrite local files with the remote Feishu version. If you have local edits that haven't been pushed yet, stash or back them up before pulling.
6. **Verify after push** — After `push --strategy patch`, run `pull` to verify the changes were applied correctly. The API may report "OK" while the actual document state differs.
7. **Reply does not resolve comments** — The `reply` command only appends a reply message. It does **not** mark the comment as resolved. The reviewer must manually click "解决" (Resolve) in the Feishu UI, or the comment will remain in the unresolved list.
5. **Use `blocks` before `patch`** — Inspect the block tree to find exact block_ids for surgical edits.
6. **Reply to comments after fixing** — Use the `reply` command to inform reviewers what was changed.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| `URL/QR Code hidden` | Wrapper script swallows output | Run `lark-cli config init --new` directly |
| `npm not found` | Node.js not installed | Install Node.js from https://nodejs.org/ then re-run `setup` |
| `lark-cli not found` | Installation failed | Re-run `setup` or manually `npm install -g @larksuite/cli` |
| `not configured` | App not set up | Run `lark-cli config init --new` |
| `space_id is missing` | No config file | Run `setup` |
| `No sync state found` | `init` not run yet | Run `setup` or `pull` |
| 0 matched files on `init` | Titles mismatch | Add `readme_title` or `title_mappings` |
| Push says "Failed!" | Token expired / permissions | Re-run `lark-cli auth login` and check Wiki edit permissions |
| **Comments invisible after push** | Used `overwrite` strategy | Comments still exist in API. Use `comments` command to view. For future edits, use `patch` or `str_replace`. |
| **"原文已被删除" on comments** | Used `block_replace` on a block that had comments | The block ID changed. Comment content is preserved but anchor is lost. Prefer `str_replace` if possible. |
| **Push says "OK" but content unchanged** | `block_insert_after` may silently fail or be misordered | Run `pull` to verify, then check block tree with `blocks` command and retry. |
| Images appear at the end of the Feishu doc | `docs +media-insert` was used directly | Run `python3 sync.py inline-images`, then `python3 sync.py inline-images --verify`. |
| Images are in the right place but visually cropped | Old oversized image tokens are still being reused | Regenerate mobile-safe assets, then run `python3 sync.py inline-images --refresh` and verify. |
| `inline-images` cannot find anchors | Captions in `visual_images` do not exactly match the text after `图示：` | Copy the caption from the local Markdown anchor, without the trailing explanation sentence. |
| `inline-images` finds too few image tokens | Images were not uploaded and upload failed | Check `lark-cli doctor`, file paths in `visual_images`, and document edit permission. |
| `1770013 relation mismatch` while replacing an image | Reusing an image token in a different image block | Use `inline-images` token repositioning instead of direct `replace_image` on a newly-created block. |

## Manual Setup (if automatic setup doesn't work)

If the wizard fails for any reason, you can set up manually:

```bash
# 1. Install lark-cli
npm install -g @larksuite/cli

# 2. Configure app (MUST see URL/QR code)
lark-cli config init --new

# 3. Log in (open the URL it prints in your browser)
lark-cli auth login

# 4. Find your space_id
lark-cli wiki spaces list

# 5. Create lark-sync.json
cat > lark-sync.json << 'EOF'
{
  "space_id": "YOUR_SPACE_ID_HERE"
}
EOF

# 6. Initialize sync state
python3 ~/.claude/skills/feishu-sync/scripts/sync.py init
```
